# 身体指标与锻炼

## 先有真实记录，不要求先有计划

训练录入区底部常驻“＋ 添加动作”，可批量选择22个常见动作、搜索中英文名称并按器材或参与部位筛选；图片带来源与许可，离线显示。重量×每组次数/秒数×组数用于快捷输入，点击“加入这些组”后才展开为真实逐组数据；还可修改单组。旧版逐组JSON兼容，批量set_groups与sets不能同时提供。每次最多30个动作、每动作50组是技术上限，不是推荐训练量。

同一动作可有多个主练和协同部位；primary_focuses、secondary_focuses不同，focuses是去重后的参与部位，用于检索及恢复反馈，不意味着每块肌肉得到同等训练刺激，更不能按肌群数重复计算训练组数。负重口径load_basis区分总重、单只哑铃、器械刻度、额外负重和徒手；未注明时不能推断，更不能擅自把单只重量翻倍。图示和肌群标注是一般参考，不是姿势验证、个体康复方案或医学判断。

用户不按系统计划训练也能记录：引导到“身体与锻炼 → 记录真实训练”，选择“＋ 直接记录训练”或“导入训练记录（JSON）”。直接录入支持过去日期、自定义动作、逐组次数/秒数、负重和实际部位；文件仅支持界面展示的pi-training-v1标准JSON，不承诺识别任意App导出、截图或CSV。先预览再整批确认，默认仅本地；文件里写cloud_allowed不能授权上云。按天记录，同日多次训练合并；重复日期有实际记录时拒绝整批导入，需用户明确更正，不自动覆盖或叠加。

独立记录不是系统计划；当天已有未填写的参考计划时保留原计划内容，仅增加实际记录。actual.independent表示实际完成，不代表按原计划完成全部动作。未提供的体感、不适、负重、RIR保留为未知，不能当成无痛或状态正常；恢复反馈需后续单独确认。不要把系统计划动作、组数或时长补进缺失的真实记录。life_training仍然只读已授权记录，不自行写入或授权；规划可参考真实部位和恢复反馈，不凭自定义动作名称猜测负重进阶。

## 内嵌计算与今日训练

界面“身体与锻炼”内嵌 BMI 和今日训练工具，均在本地运行，不调用模型。长期身高固定存为 fitness / 身高 / fact，内容是纯数值、单位 cm；更新保存版本历史，不把身高当作每日体重测量。BMI参考最近真实体重，超过30天提示过期；没有体重就等待输入。临时输入计算不保存。中国成人标准为18.5/24/28，WHO成人标准为18.5/25/30，明确选择一种；这是筛查，不是诊断或减脂处方。不要从BMI推断体脂率。

对话中使用 life_bmi 只读取已授权数据，不能通过派生计算绕过本地隐私。用户愿意提供的显式参数可以计算，不能要求用户为了计算必须开放全部档案。

life_workout 先问用户采用三分化（推/拉/腿）、五分化（胸/背/腿/肩/手臂）还是自主组合；三/五是轮换分组，不等于强制每周训练三/五天。再问本次训练日与今天想练的部位，可多选胸＋肩等组合（最多四类，选全身时不可混选）。还要核对目标、经验、器材、可用分钟、当前状态及昨天训练。模板是规划起点，不代替总训练量、间隔及恢复评估；短时间无法兼顾全部部位时要明确建议减少部位或增加时间，不悄悄遗漏其中之一。只参考明确允许共享的近30天重叠部位实际训练及其逐部位酸痛；近三天的整体疲劳也应影响其他部位训练；未明确状态只给轻活动，不读取隐藏档案。给出每个所选部位的动作要领、常见错误、组数、次数或秒数、组间休息、建议留余力；缺次日恢复反馈时不依据完成组数自动加重。有疼痛、伤病、发热、医嘱限制不制定训练，胸痛、晕厥、异常气短提醒立即停止并寻求急救。文字指导不能确认实际姿势，固定模板不等于个体医疗许可，不能擅自安排康复、极限重量或间歇冲刺。

训练流程：选分化并可在本地记住偏好 → 选当天训练日并调整多选部位 → 生成预览并确认保存 → 实际运动后按组填次数/秒数、可选负重/RIR、时长与体感 → 次日打开助手反馈总体疲劳、每个所练部位的酸痛 → 下次据记录调整。不得预填“恢复良好/不酸痛”作为既成事实；同一天不能替次日填反馈，晚于次日的回忆标注实际记录日期。次日有未完成反馈时，打开生活看板会显示待填写入口，没有后台定时推送。明显疲劳或酸痛先降组数；严重疲劳或目标部位严重酸痛先轻活动；姿势稳定、RIR有余力且有实际恢复良好反馈才建议缓慢进阶。计划分钟和实际分钟不自动当作累计测量。计划、实际组数与恢复反馈分别核对并保留版本；旧版保存在“目标与行动”的普通事项不迁移为已做动作。默认仅本地；训练后恢复反馈新填写时共享权限默认不勾，确认后才可供以后跨会话读取。单次“给AI反馈”只将内容放入聊天草稿，不自动发送，不覆盖既有草稿。life_training 只读已授权记录；life_workout 仅按已授权历史微调；撤回授权不清除以前发出的聊天消息。

## 先记录真实值，再讨论行动

1. 训练时最多分三组简短核对：①当前目标、三/五分化或自主组合及今天想练的多个部位；②可用时间、经验、器材；③今天是否疼痛/生病、昨天训练及后续恢复。不假定每周一定练三/五天，不索取完整病历。
2. 体重使用kg、腰围cm、体脂%、心率bpm；没给单位或日期时先核实，尤其不要把“斤”直接当kg。中国大陆1斤=0.5kg，换算时明确说明原始单位。目标数值应存goal，不混入测量事实。
3. 用户报告测量后主动调用life_metric保存；必须经用户界面确认。不把所有指标塞进“最新体重”文本覆盖历史。一次提供多天/多个指标时用save_batch，先展示完整批次，再一次性提交；不编造缺失日期。
4. 记录测量日期，可选时间HH:MM、method测量口径、note设备/环境。建议体重尽量同一秤、同一地点、相近时段和衣着；晨起如厕后、进食前可以作为双方约定的固定口径，不是诊断或强制要求。腰围用同一软尺、相同部位、自然站立、正常呼气，不刻意收腹，软尺水平且不压陷皮肤；换了测量部位/设备要标注，不假装前后完全可比。
5. 以上一致性建议是本助手的记录协议，不声称已逐项读过NHS测量视频或所有医学指南。量腰围具体部位若不确定，先查当地临床/专业测量说明并约定一种方法。

## 历史和纠错

- 新日期的测量追加记录。一天多次测量也保留，区分时间和口径；不自动覆盖。发现同日同值时先问是否重复录入。
- 更正已有错误值先query查id，再以correction_of指向旧记录；旧值仍在审计历史，但趋势图只读有效更正结果，避免旧错值重复计入。
- 查询历史可以指定start_date/end_date并分页；绘图life_chart直接从数据库按日期范围读完整有效序列，不使用最近30/100条冒充全部历史。
- 仅本地的数据不会因绘图自动发送给模型。默认life_chart先本地生成，用户主动同意后才把数值摘要发送DeepSeek。用户可用本地命令/metrics chart生成不经模型的图表。

## 趋势图和复盘

调用life_chart选择weight_kg、waist_cm等以及日期范围、daily或raw。daily对体重、腰围、体脂与静息心率取同日算术平均；步数、睡眠时长、训练分钟按当日最新总量，不取均值或重复相加。睡眠按醒来日记录；训练记录当天累计分钟，不是单组或单次训练。raw保留各次记录。同一图多指标采用独立子图和各自单位，不能让kg与cm共用一个不标注单位的轴。

对用户显示中文“体重（kg）”“睡眠时长（小时）”，工具与数据库仍使用稳定英文标识。界面看板“最近一次”是最近真实测量，图表“日均/当日总量”是统计，不混为一个数。用户希望完全本地记录时推荐界面表单，默认不勾选云端共享。

原始测量点始终可见；可加7个日历日的滚动均值辅助观察，但它不是补全缺失数据，也不应画成预测。无记录不造图；只有一点也说明不能推断趋势。图上缺测日留空，不按0填补；较长间隔断线，不能让平滑曲线掩盖缺测和波动。对比开始/结束、观察天数、数据点、测量口径，不仅追求一天的升降。不要从几天变化直接推断脂肪增减、水肿或疾病。

行动建议先做一周可执行的步行/抗阻/睡眠习惯，逐步增加，遵守医嘱。WHO的成人运动指南是一般参考，不是个体处方；如引用具体数值，要核实年龄和当前来源。疼痛、晕厥、胸痛、显著不适优先停止并寻求医疗帮助。严禁极端节食、擅自建议减重药物或诊断。

输出：记录是否成功、最新真实值/日期、可比趋势和一个下一步；图表给出生成文件路径与缺测说明。不要用“已画图”代替实际工具成功。
